## WP-P4-A · เก็บข้อมูลรูปงานให้ครบ (§12) — คลาวด์ไม่เกี่ยว ไม่กระทบตัวเทียบ

`tbl_task_photo` ตอนนี้มีแค่ `Path` + `Created_At` (ยืนยันจาก ARCHITECTURE.md §12)
ขาด: `file_hash` · ขนาดไฟล์ · ผู้ส่ง · เวลาถ่ายจริง

**ทำอะไร**
1. `sql/053_task_photo_meta.sql` — เพิ่มคอลัมน์แบบ **nullable ทั้งหมด** (ของเดิมต้องไม่พัง)
   `File_Hash CHAR(64) NULL` · `Bytes INT NULL` · `Sender_User_ID INT NULL` · `Taken_At DATETIME NULL`
   + `KEY idx_hash (File_Hash)`
2. จุดที่บันทึกรูป (หาเอง — อยู่ใน `api/line_webhook.php` เส้นทางรูปของงาน) เติมค่าใหม่
   - `File_Hash` = `hash_file('sha256', $path)` — ใช้ตรวจว่ารูปซ้ำ/ถูกแก้
   - `Taken_At` **อย่าเดา** ถ้าอ่านจากไฟล์ไม่ได้ให้เป็น NULL

**ห้ามทำ**
- ❌ **ห้ามเก็บพิกัด GPS ของคน** — ARCHITECTURE.md §3 ข้อ 1 เขียนไว้ว่าบ้านนี้ยังไม่มีระบบ consent
  เก็บได้เฉพาะ "พิกัดของงาน (ที่หมาย)" ซึ่งเป็นงานคนละใบ ยังไม่อนุมัติ
- ❌ ห้ามแก้รูปเดิมย้อนหลัง — ของเก่าปล่อยเป็น NULL ไป

**เกณฑ์ผ่าน**
- `php bin/smoke_tasks_render.php` ยังผ่านเท่าเดิม (36 ข้อ)
- เทสใหม่: บันทึกรูปแล้วได้ hash ตรงกับ `hash_file` ของไฟล์จริง · ไฟล์อ่านไม่ได้ = NULL ไม่ใช่สตริงว่าง
- `php bin/aim_reconcile.php` ยังตรงกัน 100% (พิสูจน์ว่าไม่กระทบสิ่งที่ถูกวัด)

## WP-P4-B · ยามเฝ้าความต่อเนื่องของ P4 เอง

ประตูบอกว่า "ตรงกัน 7 วันติด" แต่ **ไม่มีใครนับให้** — ต้องเปิด `tbl_notify_log` อ่านเอง

**ทำอะไร**
`bin/aim_reconcile.php` เพิ่มโหมด `--streak` พิมพ์ว่า "ตรงกันติดกันมาแล้วกี่วัน"
- นับจาก `tbl_notify_log` ที่ `Code='aim_reconcile'` เรียงจากใหม่ไปเก่า
- เจอ `Result != 'ok'` เมื่อไร = ตัดสตรีค
- **นับ "วัน" ไม่ใช่ "จำนวนรอบ"** — รันซ้ำ 5 ครั้งในวันเดียวต้องนับเป็น 1 วัน
  (ไม่งั้นรันมือถี่ ๆ จะทำให้ผ่านประตูปลอม ๆ)
- วันที่ไม่มีบันทึกเลย = ตัดสตรีค (ไม่ใช่ข้าม) — วันที่ไม่ได้ตรวจ ไม่ใช่วันที่ตรงกัน

**เกณฑ์ผ่าน**
- เทสที่ seed `notify_log` แล้วยืนยันว่า: 3 รอบในวันเดียว = 1 วัน · มี fail คั่น = ตัดสตรีค
  · วันหายไปกลางทาง = ตัดสตรีค
- ต้องพิสูจน์ด้วยการ **ทำให้ตกก่อน** แล้วค่อยผ่าน (กติกาบ้านนี้ — ยามที่ตกไม่ได้ ไม่ใช่ยาม)

## WP-P4-C · เอกสาร §29 consent / retention / export-delete

ARCHITECTURE.md §29 บอกว่า **"ไม่มีเอกสารเลย"** และเขียนกำกับว่า *"ต้องมีก่อนแตะ GPS"*
ตอนนี้ยังไม่แตะ GPS แต่ระบบเก็บข้อมูลคนไปแล้วหลายอย่าง (รูป · เวลาทำงาน · งานที่ได้รับมอบหมาย)

**ทำอะไร** — `docs/DATA_POLICY.md` ตอบ 4 คำถามด้วยของจริงที่วัดได้ ไม่ใช่ข้อความทั่วไป
1. เก็บอะไรบ้าง · เก็บที่ไหน (ฝั่ง LIVE / คลาวด์) — **ไล่จากตารางจริง ไม่ใช่จากความจำ**
2. เก็บนานแค่ไหน · อะไรลบอัตโนมัติแล้วบ้าง (เช่น heartbeat 7 วันใน `tbl_bridge_read`)
3. ใครดูได้ (อ้าง `canView()` และตารางสิทธิ์จริง)
4. ถ้าพนักงานขอให้ลบข้อมูลตัวเอง ต้องทำอะไรบ้าง — **ระบุชื่อตารางและลำดับการลบ**

**ห้าม** เขียนนโยบายที่ระบบทำไม่ได้จริง — เอกสารที่สัญญาเกินของที่มี แย่กว่าไม่มีเอกสาร
