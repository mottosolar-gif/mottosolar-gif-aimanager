### ③ สัญญา — นิยามของ "วัน" และ "ติดกัน" (ตรงนี้คือเนื้องานจริง ไม่ใช่การพิมพ์เลข)

**"วันที่ผ่าน"** = วันตามปฏิทิน **เวลาไทย (UTC+7)** ที่ **มีบันทึกอย่างน้อย 1 รอบ** *และ*
**ทุกรอบของวันนั้น `Result` = `ok`**
- 🔴 วันที่มี ok 4 รอบ + ไม่ ok 1 รอบ ⇒ **วันนั้นไม่ผ่าน** (fail-closed ตามข้อห้าม 6: *ไม่รู้จัก = ปฏิเสธ*)
  — ห้ามใช้ท่า "วันไหนมี ok สักรอบก็ถือว่าผ่าน" เพราะนั่นคือการซ่อนความล้มเหลวจริงไว้ใต้การรันซ้ำ
- ค่า `Result` อื่นทุกค่า (รวม `NULL` · สตริงว่าง · ค่าที่ไม่รู้จัก) = **ไม่ผ่าน**

**"สตรีค"** = จำนวน *วันที่ผ่าน* ที่ต่อเนื่องกันโดยไม่มีวันว่างคั่น นับถอยหลังจาก **วันฐาน**
- **รันซ้ำกี่ครั้งในวันเดียวก็นับเป็น 1 วัน** — ไม่งั้นรันมือรัว ๆ ก็ผ่านประตูปลอมได้
- **วันที่ไม่มีบันทึกเลย = ตัดสตรีค ไม่ใช่ข้าม** — วันที่ไม่ได้ตรวจ ไม่ใช่วันที่ตรงกัน

**🔑 "วันฐาน" = วันล่าสุดที่มีบันทึก ไม่ใช่ "วันนี้"** — จุดนี้พลาดง่ายและพลาดแล้วเงียบ:
งานจริงรัน **23:30** ⇒ ถ้าใช้ "วันนี้" เป็นฐาน ตัวนับจะตอบ **0 ทุกเช้าจนถึงสี่ทุ่มครึ่ง**
= ตัววัดที่ตอบผิดวันละ 23 ชั่วโมงครึ่ง ซึ่ง **น่ากลัวกว่าไม่มีตัววัด** (D-P0-16 จ่ายบทเรียนนี้มาแล้ว 2 ครั้งในวันเดียว)

**แต่ห้ามให้ "วันฐาน" กลายเป็นช่องโหว่** ⇒ ต้องพิมพ์ 3 อย่างนี้เสมอ ทุกครั้ง:
```
สตรีค          : N วัน  (ประตูต้องการ 7)
บันทึกล่าสุด    : YYYY-MM-DD  (ห่างจากตอนนี้ M วัน)
ช่วงที่นับได้    : YYYY-MM-DD ถึง YYYY-MM-DD
```
- ถ้า **บันทึกล่าสุดเก่ากว่า "เมื่อวาน"** ⇒ ขึ้นคำเตือนตัวใหญ่ว่า **ตัวเทียบอาจไม่ได้รันแล้ว**
  และสตรีคที่นับได้ **ไม่มีความหมาย** จนกว่าจะรู้ว่าทำไมมันหยุด
  (ไม่งั้นจะเกิดเคส "สตรีค 7 วัน ✅" ทั้งที่ยามตายไปตั้งแต่อาทิตย์ที่แล้ว)

**เขตเวลา — ห้ามพลาดท่าเดิม (D-P0-16):** ห้ามเทียบสตริงเวลาข้ามรูปแบบ · ให้ตัดวันจากคอลัมน์เวลาจริง
ตามปฏิทินไทย · บันทึก 23:50 กับ 00:10 = **คนละวัน** เสมอ

**พฤติกรรมอื่นที่ต้องตายตัว:**
- โหมดนี้ **ห้ามเขียนอะไรลงฐาน · ห้ามยิง LINE · ห้ามแตะไฟล์** (ข้อห้าม 4 ของบ้านนี้)
- ไม่มีบันทึกเลยทั้งตาราง ⇒ ตอบ `สตรีค 0 · ไม่มีข้อมูล` **ไม่ใช่ crash และไม่ใช่เดา**
- **exit code:** `0` = อ่านสำเร็จ (ไม่ว่าสตรีคจะกี่วัน) · `1` = อ่านไม่ได้/ไม่มีตาราง
  ⇒ ตัวนี้เป็น **ตัวรายงาน ไม่ใช่ตัวตัดสิน** — คนตัดสินว่าจะเปิด P5 ไหม ไม่ใช่ exit code
- ข้อความเป็นภาษาไทย อ่านแล้วตัดสินใจได้ทันที · **ไม่ต้องใช้น้ำเสียงน้องกุ้ง** (กฎนั้นคุมข้อความที่ถึงผู้ใช้
  ใน `queryEngine.ts` ไม่ใช่เครื่องมือ ops บนเครื่อง)

### ④ เกณฑ์ผ่าน

`bin/smoke_reconcile_streak.php` ต้อง seed ข้อมูลเองแล้วยืนยันครบ 7 เคสนี้ (อย่างน้อย):

| # | สถานการณ์ | ต้องได้ |
|---|---|---|
| 1 | 3 รอบในวันเดียว ok ทั้งหมด | นับเป็น **1 วัน** |
| 2 | วันหนึ่งมี ok 4 + ไม่ ok 1 | วันนั้น **ไม่ผ่าน** และ **ตัดสตรีค** |
| 3 | วันหายไปกลางทาง (มี 1,2,4 ก.ย. ไม่มี 3) | สตรีคนับได้ **1** (แค่ 4 ก.ย.) |
| 4 | `Result` เป็น `NULL` / สตริงว่าง / ค่าแปลก | **ไม่ผ่าน** (fail-closed) |
| 5 | ตารางว่างเปล่า | ตอบ 0 + บอกว่าไม่มีข้อมูล · **ไม่ crash** |
| 6 | บันทึกล่าสุดเก่ากว่าเมื่อวาน | ขึ้น **คำเตือนว่าตัวเทียบอาจตาย** |
| 7 | บันทึก 23:50 กับ 00:10 คนละวัน | นับเป็น **2 วัน** ไม่ใช่ 1 |

**⛔ เขียวเฉย ๆ ไม่นับว่าเสร็จ — ต้องพิสูจน์ว่ายามตกได้จริง** (บทเรียนที่แพงที่สุดของโปรเจกต์นี้ จ่ายมาแล้ว 3 ครั้ง)
ทำ sabotage อย่างน้อย 4 ท่านี้ **ทีละท่า** แล้วรายงานว่าตกกี่ข้อ ก่อนคืนค่า:

| sabotage | เทสที่ต้องตก |
|---|---|
| เอาการยุบรอบในวันเดียวออก (นับรอบแทนวัน) | #1 |
| เปลี่ยนเงื่อนไขให้ "มี ok สักรอบ = ผ่าน" | #2 |
| เอาการเช็ควันว่างคั่นออก | #3 |
| ให้ค่า `Result` ที่ไม่รู้จักผ่านไปได้ | #4 |

⚠ **ต้องยืนยันว่า sabotage แทนที่สำเร็จจริงก่อนรายงาน** — เคยพลาดมาแล้ว: `sed` ไม่ตรงช่องว่าง
แล้วรายงานว่าเขียว ทั้งที่ไม่ได้แก้อะไรเลย ผลจึงออกมาเหมือนตอนยามแข็งแรงเป๊ะ

**รายงานปิดงานต้องมี:** sabotage อะไร → ตกกี่ข้อ → คืน → ผ่านเท่าไร · **และผลรัน `--streak` กับข้อมูลจริง**
(นี่คือครั้งแรกที่จะมีคนตอบได้ว่า P4 เดินมากี่วันแล้ว — เขียนตัวเลขจริงมาด้วย)

**จำนวนเทสห้ามลดลง** · สไตล์ PHP ต้องเข้ากับ estate: **ห้าม** arrow fn · `??=` · `declare(strict_types)` ·
typed property · return type (ไม่มีเทสบังคับข้อนี้แล้ว — เป็นวินัยของคนเขียน)

### ⑥ เจออะไรให้หยุดถาม (อย่าตัดสินใจเอง)

1. **`--streak` หรือ `smoke_reconcile_streak.php` มีอยู่แล้ว** ⇒ หยุด รายงานผลรันของจริง ใบนี้อาจปิดไปแล้ว
2. **ต้องแก้ตรรกะเทียบเดิมถึงจะใส่ `--streak` ได้** ⇒ หยุดทันที นั่นคือการแตะสิ่งที่ถูกวัดอยู่
3. **`tbl_notify_log` ไม่มีคอลัมน์ตามที่ใบสั่งเดาไว้** ⇒ หยุด · **ห้ามสร้าง/แก้ตารางหรือคอลัมน์เอง**
4. **`Result` มีค่าที่ดูเหมือนผ่านแต่สะกดคนละแบบ** ⇒ หยุดถาม ห้ามเดาว่าให้นับเป็นผ่าน
5. **นับแล้วพบว่าสตรีคขาดไปแล้ว หรือสั้นกว่าที่ทุกคนเข้าใจ** ⇒ **รายงานตามจริง ห้ามแก้ข้อมูล
   ห้ามผ่อนนิยามให้ตัวเลขสวยขึ้น** — ตัวเลขที่น่าเกลียดแต่จริง คือทั้งหมดที่ใบนี้มีค่า
   (ความน่ารักห้ามทำให้ข่าวร้ายอ่อนลง — กติกาบ้านข้อ 4)

## WP-P4-C · เอกสาร §29 consent / retention / export-delete

ARCHITECTURE.md §29 บอกว่า **"ไม่มีเอกสารเลย"** และเขียนกำกับว่า *"ต้องมีก่อนแตะ GPS"*
ตอนนี้ยังไม่แตะ GPS แต่ระบบเก็บข้อมูลคนไปแล้วหลายอย่าง (รูป · เวลาทำงาน · งานที่ได้รับมอบหมาย)

**ทำอะไร** — `docs/DATA_POLICY.md` ตอบ 4 คำถามด้วยของจริงที่วัดได้ ไม่ใช่ข้อความทั่วไป
1. เก็บอะไรบ้าง · เก็บที่ไหน (ฝั่ง LIVE / คลาวด์) — **ไล่จากตารางจริง ไม่ใช่จากความจำ**
2. เก็บนานแค่ไหน · อะไรลบอัตโนมัติแล้วบ้าง (เช่น heartbeat 7 วันใน `tbl_bridge_read`)
3. ใครดูได้ (อ้าง `canView()` และตารางสิทธิ์จริง)
4. ถ้าพนักงานขอให้ลบข้อมูลตัวเอง ต้องทำอะไรบ้าง — **ระบุชื่อตารางและลำดับการลบ**

**ห้าม** เขียนนโยบายที่ระบบทำไม่ได้จริง — เอกสารที่สัญญาเกินของที่มี แย่กว่าไม่มีเอกสาร
