## WP-P5-A · ทำให้ "ของเก่าหยุดจริง" พิสูจน์ได้ ก่อนย้ายอะไรสักอย่าง

**ทำใบนี้ก่อนใบอื่นเสมอ** — ถ้าไม่มีตัวพิสูจน์ ย้ายไปแล้วจะไม่มีทางรู้ว่าของเก่าหยุดหรือยัง

**ทำอะไร** — `bin/legacy_silence_check.php` ตอบคำถามเดียว:
*"ตั้งแต่ย้ายมา โค้ดเก่ายังทำงานอยู่ไหม"*

วิธีที่ **ห้ามใช้**: ดูว่าไฟล์ยังอยู่ไหม / grep ว่ามีใครเรียกไหม
— สองอย่างนี้ตอบได้แค่ "มีโอกาสถูกเรียก" ไม่ใช่ "ถูกเรียกจริง"

วิธีที่ต้องใช้: **หลักฐานจากของที่มันทิ้งไว้จริง**
- แถวใหม่ในตารางที่มีแต่ของเก่าเขียน
- บรรทัดใหม่ใน log ของมัน
- `LastRunTime` ของ scheduled task ที่ควรถูกปิดไปแล้ว

**เกณฑ์ผ่าน**
- ตรวจได้อย่างน้อย 3 สัญญาณข้างต้น · รายงานเป็น "เงียบมาแล้วกี่วัน" ไม่ใช่ ok/fail เฉย ๆ
- เทส: จำลองว่าของเก่าเพิ่งเขียนแถวใหม่ → ต้องฟ้อง · ไม่มีอะไรใหม่ → เงียบ
- **พิสูจน์ว่าตกได้จริงก่อนบอกว่าเสร็จ**

**4 ชนิดสัญญาณ** (เกินเกณฑ์ที่ใบนี้ขอไว้ 3): `db` แถวใหม่ในตาราง · `file`/`log` ร่องรอยใหม่ในพาธ
· `task` สถานะ + LastRunTime + Next Run ของ scheduled task

**exit code** (ขนบเดียวกับ `feed_parity_check`): `0` เงียบครบ = ตัดของเก่าได้ · `1` ของเก่ายังทำงาน
= **ห้ามลบ** · `2` ตรวจไม่ได้ / ยังไม่มีสัญญาณลงทะเบียน — **ไม่ใช่ผ่าน**

**กติกาที่ฝังไว้ในโค้ด (ทุกข้อมาจากบทเรียนจริงของ estate)**
- 🔴 **"อ่านไม่ได้" ห้ามกลายเป็น "เงียบ"** — พาธหาย · ตารางหาย · คิวรีพัง · ทะเบียนอ่านไม่ได้ = `unknown` เสมอ
- 🔴 **ไม่มีสัญญาณเลย = exit 2** (ยังไม่มีใครลงทะเบียนของที่ต้องเฝ้า ≠ ของเก่าหยุดแล้ว)
- 🔴 ลำดับความร้ายแรง `active > unknown > silent` — ตัวที่เงียบห้ามกลบตัวที่ตรวจไม่ได้
- 🔴 ทะเบียนเป็น**ข้อมูลที่คนแก้ได้** ⇒ `kind=db` รับเฉพาะ identifier ที่ผ่าน regex + ค่ากรองผูกเป็นพารามิเตอร์
  **ตั้งใจไม่รองรับ WHERE ดิบ**

**ผ่านเกณฑ์ "พิสูจน์ว่าตกได้จริง" แล้ว** — ยามจำลองไฟล์/แถวใหม่หลังหมุดจริงแล้วตรวจว่าฟ้อง
· และ audit หลาย agent (ทุกข้อยืนยันโดยผู้ตรวจอิสระ 3 คน) จับบั๊กในตัวเครื่องมือได้ **6 ข้อ ซึ่งแก้แล้วทั้งหมด**:
1. **[critical]** `Cutover_At` ที่เป็นอนาคต ⇒ ทุกร่องรอยเก่ากว่าหมุดโดยโครงสร้าง = `silent` 100% + exit 0
   "ตัดของเก่าได้" ทั้งที่ของเก่าเพิ่งเขียนเมื่อกี้ (การลงทะเบียนล่วงหน้าก่อนวันสลับคือการใช้งานปกติ)
2. **[high]** `kind=task` ดูแค่ LastRunTime ⇒ task ที่ยัง Enabled รอรอบถัดไปถูกนับว่าหยุด
   — เคสร้ายสุดคือ legacy task รายสัปดาห์: "เงียบ 6 วัน" ทั้งสัปดาห์ ⇒ ลบโค้ดเก่า ⇒ จันทร์หน้ายิงเข้าที่ว่าง
3. **[high]** ทะเบียนกรอกตัวกรองครึ่งคู่ ⇒ ไม่แมตช์อะไรเลย ⇒ รายงานว่าเงียบ
4. **[high]** อ่านทะเบียนไม่ได้ แยกไม่ออกจากทะเบียนว่าง ⇒ ยามข้ามทั้งบล็อกเงียบ ๆ
5. **[medium]** ไม่นับ mtime ของโฟลเดอร์ ⇒ โค้ดเก่าที่เขียนไฟล์แล้วลบทิ้งถูกนับว่าเงียบ
6. **[medium]** timezone: เทียบ `filemtime` (epoch) กับ `strtotime(DATETIME)` ตาม tz แวดล้อม (php.ini ไม่ตั้ง `date.timezone`)

**สัญญาณจริงที่เฝ้าอยู่ตอนนี้ 2 ตัว** (ของที่เคยเขียนไว้ว่า "เก็บไว้เฝ้าดู" แต่ไม่มีใครมีเครื่องมือดู):
`cim/chcustoms/admin/temp_removal_photos` · `cim/chcustoms/import_file` — หมุด `2026-09-03 00:00`
⇒ ผลวัดจริง: **เงียบทั้งคู่** (ณ 2026-09-06 เงียบ 3.2 วัน) = เข้าเงื่อนไขให้ตัดของเก่าได้ รอคำสั่งเจ้าของระบบ

**วิธีใช้กับระบบถัดไปที่ย้ายขึ้น Cloudflare** — พอระบบใดถึงขั้น 3 (สลับความเป็นเจ้าของ) ให้ INSERT สัญญาณ
ของมันลง `tbl_legacy_cutover` (ตาราง/ไฟล์/task ที่มีแต่โค้ดเก่าเขียน) พร้อม `Cutover_At` = เวลาที่สลับจริง
แล้วปล่อยให้ `selfcheck` เฝ้าให้ทุกวัน · ตัดของเก่าได้เมื่อ `legacy_silence_check` คืน exit 0 เท่านั้น
