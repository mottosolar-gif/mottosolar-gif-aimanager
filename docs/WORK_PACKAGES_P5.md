### ③ สัญญา

**ต้องตรวจครบ 3 สัญญาณ และรายงานแยกกันทีละตัว** — ระบบหนึ่งอาจดูตายจากสัญญาณหนึ่งแต่ยังเป็นจากอีกสัญญาณ

| # | สัญญาณ | อ่านจาก |
|---|---|---|
| 1 | แถวใหม่ในตารางที่มีแต่ของเก่าเขียน | `MAX(Created_At)`, `MAX(Updated_At)` ของ `tbl_tool` |
| 2 | บรรทัดใหม่ใน log ของมัน | `line_webhook.log` บรรทัด `tool loan …` — เวลาบรรทัดล่าสุด |
| 3 | scheduled task ที่ควรถูกปิดไปแล้ว | `LastRunTime` ของ `ksk-tool-draft-sweep` · `ksk-tool-loan-evening` · `ksk-tool-loan-morning` |

**🔑 เส้นแบ่ง "ตั้งแต่ย้ายมา" ต้องเป็นค่าที่จดไว้ ไม่ใช่ค่าที่เดา**
ตอนย้ายระบบใน WP-P5-B ต้องบันทึก **เวลาที่ตัดสวิตช์** ลงตารางถาวร (เช่น `tbl_legacy_cutover`:
`System_Key` · `Cutover_At` · `Note`) แล้วใบนี้อ่านค่านั้นมาเป็นเส้นแบ่ง
⇒ ถ้ายังไม่มีแถวของระบบนั้น = **ยังไม่ได้ย้าย** ⇒ รายงานว่า "ยังไม่ถึงคิว" ไม่ใช่ "เงียบ 0 วัน"
(สองอย่างนี้ต่างกันสิ้นเชิง — อันหลังแปลว่าเพิ่งมีคนใช้เมื่อกี้)

**⛔ fail-closed — ข้อที่พลาดแล้วอันตรายที่สุดของใบนี้**
อ่านสัญญาณไหนไม่ได้ (schtasks ล้ม · ไม่มีตาราง · เปิด log ไม่ได้) ⇒ **ต้องรายงานว่า "ตรวจไม่ได้"
ห้ามรายงานว่าเงียบเด็ดขาด** — "เงียบเพราะไม่มีใครใช้" กับ "เงียบเพราะมองไม่เห็น" หน้าตาเหมือนกัน
แต่ความหมายตรงข้าม · การรายงานเงียบทั้งที่มองไม่เห็น = **สร้าง D-004 ขึ้นมาใหม่ด้วยมือตัวเอง**
(*"สัญญาที่ไม่มีตัวบังคับใช้ = ไม่มีสัญญา"* — heartbeat เคยเงียบข้ามคืน 8.5 ชม. โดยไม่มีใครรู้)

**รูปแบบผลลัพธ์** — บรรทัดเดียวต่อสัญญาณ อ่านแล้วตัดสินใจได้ทันที:
```
ระบบเครื่องมือ (tool)   ตัดสวิตช์เมื่อ 2026-09-10 14:00
  1. ตาราง tbl_tool     เงียบมา 6 วัน   (แถวล่าสุด 2026-09-10 13:42)
  2. log tool loan      🔴 ยังมีอยู่!   (บรรทัดล่าสุด 2026-09-16 09:15 — หลังตัดสวิตช์ 6 วัน)
  3. task ksk-tool-*    ksk-tool-draft-sweep ยังรันอยู่ (LastRun 2026-09-16 09:10)
⇒ ❌ ของเก่ายังไม่หยุด — ห้ามขึ้นระบบถัดไป
```

- **exit 0 = อ่านครบทุกสัญญาณ** (ไม่ว่าผลจะเงียบหรือไม่เงียบ) · **exit 1 = มีสัญญาณที่อ่านไม่ได้**
  ⇒ เป็น **ตัวรายงาน ไม่ใช่ตัวตัดสิน** คนตัดสินว่าจะขึ้นระบบถัดไปไหม
- ห้ามยิง LINE ในใบนี้ (การแจ้งเตือนเป็นงานคนละใบ ต้องขออนุมัติของมันเอง)

### ④ เกณฑ์ผ่าน

`bin/smoke_legacy_silence.php` ต้อง seed เองแล้วยืนยันครบ:

| # | สถานการณ์ | ต้องได้ |
|---|---|---|
| 1 | ไม่มีแถวใน `tbl_legacy_cutover` | **"ยังไม่ถึงคิว"** ไม่ใช่ "เงียบ 0 วัน" |
| 2 | ตัดสวิตช์แล้ว ไม่มีอะไรใหม่เลยทั้ง 3 สัญญาณ | เงียบ N วัน · ทั้ง 3 เขียว |
| 3 | มีแถวใหม่ใน `tbl_tool` **หลัง** เวลาตัดสวิตช์ | 🔴 ฟ้องสัญญาณ 1 |
| 4 | มีบรรทัด log ใหม่หลังตัดสวิตช์ | 🔴 ฟ้องสัญญาณ 2 |
| 5 | task ยัง `LastRun` หลังตัดสวิตช์ | 🔴 ฟ้องสัญญาณ 3 |
| 6 | อ่าน `schtasks` ไม่ได้ (จำลองให้ล้ม) | **"ตรวจไม่ได้" + exit 1** ห้ามบอกว่าเงียบ |
| 7 | แถวใหม่ที่เกิด **ก่อน** เวลาตัดสวิตช์ | ไม่ฟ้อง (ของเก่าก่อนย้าย ไม่ใช่การละเมิด) |

**⛔ เขียวเฉย ๆ ไม่นับ — ต้อง sabotage ให้ตกจริงก่อน** อย่างน้อย 3 ท่า รายงานว่าตกข้อไหน:

| sabotage | เทสที่ต้องตก |
|---|---|
| เอาการเทียบกับ `Cutover_At` ออก (นับทุกแถว) | #7 |
| ให้กรณีอ่านสัญญาณไม่ได้ตกไปเป็น "เงียบ" | #6 |
| เอาการตรวจ `LastRunTime` ออก | #5 |

⚠ **ยืนยันว่า sabotage แทนที่สำเร็จจริงก่อนรายงานเสมอ** — เคยพลาด: `sed` ไม่ตรงช่องว่าง
แล้วรายงานว่าเขียว ทั้งที่ไม่ได้แก้อะไรเลย

## WP-P5-B · ย้ายระบบเครื่องมือเป็นระบบแรก (ตามลำดับในแผน)

เลือกเครื่องมือก่อนเพราะ **ผิดพลาดแล้วเสียหายน้อยที่สุด** — ของหายรู้ตัวได้ทันที ต่างจากใบลาที่ผิดแล้วไปถึงเงินเดือน

**ก่อนเขียนโค้ดสักบรรทัด ต้องส่งคำตอบ 3 ข้อนี้ให้ Claude ตรวจก่อน**
1. ตอนนี้ใครเขียน `tbl_tool` / `tbl_tool_loan` บ้าง — **ไล่จากโค้ดจริงทุกไฟล์** ไม่ใช่จากความจำ
2. ย้ายแล้ว **ใครเป็นเจ้าของความจริง** (ฝั่ง LIVE เหมือน `tbl_task` หรือไม่)
3. ระหว่างย้าย มีช่วงไหนที่ทั้งสองระบบเขียนพร้อมกันได้ไหม — **ถ้ามี ห้ามเริ่ม** ต้องออกแบบใหม่

**ข้อบังคับ**
- ทำตามแบบเดียวกับ `tbl_task` ที่ตัดสินไว้ใน D-P0-17: **ทางเดียว LIVE → คลาวด์ · ห้ามเขียนกลับ**
- `bin/smoke_tool_loan.php` และ `smoke_tool_loan_draft.php` ต้องผ่านเท่าเดิมตลอดทาง
- ห้ามแตะกติกา "ใบเบิกต้องเป็น draft จนกว่าจะรู้ชื่อผู้เบิก" (CLAUDE.md — เคยเกิดของค้างที่ไม่รู้ว่าใครถือ)

## WP-P5-C · 12 ไฟล์ที่ยังอ่านตารางตรง

แผนบอกว่ามี "12 ไฟล์ CIM" ที่ต้องแก้ให้เรียกท่อใหม่
⚠ **แต่โฟลเดอร์ CIM ถูกย้ายของออกหมดแล้ว (2026-08-28)** ⇒ ตัวเลข 12 อาจไม่ตรงแล้ว

**งานแรกของใบนี้คือ "นับใหม่" ไม่ใช่ "แก้ตามตัวเลขเดิม"**
- ไล่หาไฟล์ที่ยัง `SELECT` ตารางงาน/เครื่องมือตรง ๆ แทนที่จะผ่าน `lib/`
- รายงานเป็นรายการจริงพร้อมเลขบรรทัด แล้ว **หยุด รอ Claude ตรวจก่อนแก้**

**เหตุผลที่ต้องหยุด:** ตัวเลขในแผนเขียนไว้ตั้งแต่ 26 ส.ค. และ estate เปลี่ยนไปมากตั้งแต่นั้น

(บทเรียนจริง: ข้อสรุปว่า "ยังทำไม่ได้" ของ `ksk_send_daily.php` หมดอายุไปแล้วโดยไม่มีใครรู้)

1. **ย้ายทีละระบบ** — ห้ามย้ายสองระบบพร้อมกัน ผิดแล้วแยกไม่ออกว่าอันไหนพัง
2. **ของเก่าต้องหยุดจริง** ก่อนขึ้นระบบถัดไป — พิสูจน์ด้วย WP-P5-A ไม่ใช่ด้วยความมั่นใจ
3. **ห้ามลบโค้ดเก่าในรอบเดียวกับที่ย้าย** — ปิดสวิตช์ก่อน เฝ้าดู แล้วค่อยลบรอบถัดไป
4. ทุกใบต้องผ่านประตูเดิมทั้งหมด (`aim_reconcile` · `selfcheck` · smoke ทุกตัว) **จำนวนเทสห้ามลดลง**
