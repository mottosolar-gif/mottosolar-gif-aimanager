## WP-P0-1 · ตั้ง repo + โครงกระดูก

**เป้าหมาย** สร้างที่อยู่ถาวรของโค้ด AI Manager พร้อมสายพาน deploy อัตโนมัติ

**ไฟล์ที่แตะได้** repo ใหม่ทั้งหมด (ว่างเปล่า)
**ห้ามแตะ** ทุกอย่างใน `C:\WebApp` (ใบนี้ไม่ยุ่งกับเครื่องนี้เลย)

**สัญญา**
- repo ชื่อ `aim` บนบัญชี GitHub `mottosolar-gif` (private)
- TypeScript ทั้งหมด · โครง:
  ```
  aim/
    worker/        Cloudflare Worker (ชั้นหน้า)
    bridge/        ตัวส่งข้อมูลฝั่ง cim-server (PHP — ดู WP-P0-5)
    schema/        SQL ของ D1
    docs/          ย้ายเอกสาร 4 ฉบับจาก vendor-ksk/docs/ai-manager มาที่นี่
    .github/workflows/deploy.yml
  ```
- `deploy.yml`: push ที่ `main` → `wrangler deploy` (ใช้ secret `CLOUDFLARE_API_TOKEN`)
- **ห้าม commit ความลับใด ๆ** — ทุกค่าผ่าน GitHub Secrets / Cloudflare Secrets เท่านั้น

**เกณฑ์ผ่าน** `npm ci && npm run typecheck && npm test` เขียวบนเครื่อง CI · workflow รันได้ (แม้ deploy จะยังล้มเพราะรอ token)
**ยาม** `.gitignore` ต้องกัน `.dev.vars` · `*.env` · `wrangler.toml` ที่มีค่า secret
**หยุดถามเมื่อ** ไม่มีสิทธิ์สร้าง repo · หรือพบว่า repo ชื่อนี้มีอยู่แล้ว

## WP-P0-2 · Worker: รับ event + ตรวจลายเซ็น + เข้าคิว

**เป้าหมาย** ประตูหน้าที่รับของแล้ววางลงคิวทันที ไม่ทำงานหนักในคำขอ (สเปค §32)

**ไฟล์ที่แตะได้** `worker/**`
**ห้ามแตะ** อะไรก็ตามที่อยู่นอก repo

**สัญญา**
- `POST /ingest/line` — รับ payload ที่ fan-out ส่งมา
  - ตรวจสิทธิ์ด้วย **ความลับร่วม** ใน header `X-AIM-Key` (`hash_equals`-style constant time)
  - ถ้า header ผิด → `403` และ**ไม่ทิ้งร่องรอยว่าผิดตรงไหน**
  - ตรวจ `idempotency key` = LINE `webhookEventId` → ถ้าเคยเห็นแล้วตอบ `200 {"dup":true}` โดยไม่ทำอะไรซ้ำ
  - เขียนลงคิวแล้วตอบ `200` — เป้าหมาย **ต่ำกว่า 50ms**
- `GET /healthz` → `{"ok":true,"ts":...,"queueDepth":N,"lastIngestAt":...}`
- ทุก request เขียน log ที่มี: เวลา · ชนิด event · ผลลัพธ์ · **ห้าม log เนื้อข้อความของผู้ใช้**

**เกณฑ์ผ่าน**
- ยิง event เดิม 3 ครั้ง → เกิดงานในคิว **1 งาน** เท่านั้น
- ยิงโดยไม่มี header → 403 ทุกครั้ง
- unit test ครอบ: ผ่าน · header ผิด · ซ้ำ · payload พัง

**ยาม** ห้ามมี `console.log` ที่พิมพ์ตัวแปรที่มีข้อความผู้ใช้หรือคีย์
**หยุดถามเมื่อ** จะต้องเลือกระหว่าง Cloudflare Queues (ต้องแพลนเสียเงิน) กับคิวในตาราง D1 — **ค่าตั้งต้นคือ D1** ห้ามเปิดของที่มีค่าใช้จ่ายเอง

## WP-P0-3 · ฐานข้อมูล D1 + schema ตั้งต้น

**เป้าหมาย** ที่เก็บความจริงของบ้านใหม่ ที่ย้ายบ้านได้

**ไฟล์ที่แตะได้** `schema/**` · `worker/src/db/**`

**สัญญา** (ตารางขั้นต่ำของ P0 — ยังไม่ต้องมีตารางงาน)
| ตาราง | ไว้ทำอะไร |
|---|---|
| `inbox_event` | event ดิบที่รับเข้ามา + `event_id` UNIQUE (กันซ้ำ) + สถานะ |
| `job_queue` | งานรอทำ + `attempts` + `next_run_at` + `idem_key` UNIQUE |
| `person` | คน — เก็บ **รหัสแทนตัว (`W07`) + แผนก + บทบาท เท่านั้น** |
| `person_link` | ผูก `line_user_id` ↔ รหัสแทนตัว |
| `ledger` | บันทึกทุกการตัดสินของระบบ/AI |
| `sync_state` | ท่ออ่านซิงก์ถึงไหนแล้ว + เวลาล่าสุด |

**ข้อบังคับ**
- **ห้ามมีคอลัมน์ชื่อจริง/นามสกุล/เบอร์โทร/เหตุผลการลา ในฐานบนคลาวด์** (คำสั่งพี่เต้ 27 ส.ค.)
- ใช้ SQL มาตรฐาน · สถานะเป็น TEXT ไม่ใช่ ENUM · เวลาเก็บเป็น UTC ISO-8601 พร้อมคอลัมน์แยกสำหรับเวลาไทยที่ใช้แสดงผล
- ทุกตารางมี `created_at` และตารางที่มีเหตุการณ์ต้องมี **เวลาที่เหตุการณ์เกิดจริง** แยกจากเวลาที่บันทึก

**เกณฑ์ผ่าน** migration รันซ้ำได้ (idempotent) · มีสคริปต์ `npm run db:dump` ที่ดึงข้อมูลทั้งหมดออกเป็นไฟล์ได้
**ยาม** สคริปต์ตรวจว่า schema ไม่มีคำต้องห้าม (`name` `fullname` `phone` `reason`) ในตารางที่เก็บข้อมูลคน
**หยุดถามเมื่อ** ต้องเก็บอะไรที่ดูเหมือนข้อมูลส่วนบุคคล

## WP-P0-4 · Cron + สมุดบันทึก + ตัวกินคิว

**เป้าหมาย** ให้ระบบมีนาฬิกาของตัวเองที่อยู่นอกทั้งสองเครื่อง

**สัญญา**
- Cron Trigger ทุก 1 นาที → หยิบงานจากคิว (ทีละไม่เกิน N) → ทำ → เขียนผลลง `ledger`
- **P0 ยังไม่ต้องเรียก AI และยังไม่ต้องตอบ LINE** — งานเดียวของ P0 คือ *บันทึกว่าได้ยินอะไร*
- retry: exponential backoff · เกิน 5 ครั้ง → `dead` + บันทึกเหตุผล **ห้ามเงียบ**
- ทุกครั้งที่ Cron ทำงานต้องเขียน 1 บรรทัดเสมอ **แม้ไม่มีงาน** (การเงียบคือข้อมูล — กติกาเดียวกับ heartbeat)

**เกณฑ์ผ่าน** ปล่อยทิ้งไว้ 30 นาที แล้วเปิด `ledger` ต้องเห็นครบทุกนาที ไม่มีช่องหาย
**หยุดถามเมื่อ** Cron ฟรีชนเพดานของแพลน

## WP-P0-5 · ตัวส่งต่อฝั่ง cim-server (fan-out) — ⚠ แตะระบบ LIVE

**เป้าหมาย** ให้บ้านใหม่ได้ยินสิ่งที่ LINE ส่งมา โดย**ไม่เปลี่ยนพฤติกรรมของระบบเดิมแม้แต่นิดเดียว**

**ไฟล์ที่แตะได้** `C:\WebApp\vendor-ksk\api\line_webhook.php` (แทรกได้จุดเดียว) · `lib/aim_forward.php` (ไฟล์ใหม่) · `config/aim.credentials.php` (ไฟล์ใหม่ ไม่เข้า git)
**ห้ามแตะเด็ดขาด** ตรรกะเดิมทุกบรรทัด · ลำดับการทำงานเดิม · ข้อความตอบผู้ใช้เดิม · ตารางฐานข้อมูลใด ๆ

**สัญญา**
- แทรก **หลัง** `ll_verify_signature()` ผ่านแล้ว และ **ก่อน** `foreach ($events ...)`
- ส่ง `POST` ไป `https://<worker>/ingest/line` พร้อม header `X-AIM-Key`
- **timeout รวมต้องไม่เกิน 1.5 วินาที** และล้มเหลวทุกกรณีต้อง **ไม่โยน exception ออกมา** (`try/catch` + `@`)
- ล้มเหลว → เขียนบรรทัดเดียวลง log แล้ว**เดินหน้าต่อทันที** — ระบบเดิมต้องทำงานได้ 100% แม้คลาวด์ตายสนิท
- ระยะ P0 ส่งเฉพาะ event ที่มาจาก **กลุ่มทดสอบ** (`source.groupId` ตรงกับค่าใน config) — event ของผู้ใช้จริงยังไม่ส่งออก
- ปิดสวิตช์ได้ทันทีด้วยค่าเดียวใน config (`enabled => false`)

**เกณฑ์ผ่าน**
1. ปิดคลาวด์ทั้งหมดแล้วใช้งานระบบเดิมครบทุกฟีเจอร์ (ลา · งาน · 5ส · เครื่องมือ · ลงเวลา) — **ต้องเหมือนเดิมทุกอย่าง**
2. `php -l` ผ่าน + `bin/smoke_tasks_render.php` ยังได้ 36/36
3. วัดเวลา webhook ก่อน/หลังแก้ — ต้องเพิ่มไม่เกิน 200ms ในกรณีปกติ
4. ทดสอบกรณีคลาวด์ตอบช้า (จำลอง) → webhook เดิมต้องไม่ช้าเกิน 1.5 วิ

**ยาม** เพิ่มเคสใน smoke: "คลาวด์ล่ม → เส้นทางเดิมยังตอบปกติ"
**หยุดถามเมื่อ** ต้องแก้อะไรนอกจุดที่ระบุ · หรือพบว่าต้องเปลี่ยนลำดับการทำงานเดิม

## WP-P0-6 · ประตูปิด P0 (ทดสอบครบวง)

**เกณฑ์ผ่านทั้งเฟส** — ต้องผ่านครบทุกข้อจึงขึ้น P1 ได้
1. พิมพ์ข้อความในกลุ่มทดสอบ → เห็นบันทึกใน `ledger` ของคลาวด์ภายใน 1 นาที
2. ยิงซ้ำ 3 ครั้ง → บันทึกครั้งเดียว
3. ปิดคลาวด์ → ระบบเดิมทำงานครบทุกฟีเจอร์
4. ปิด cim-server → Cron คลาวด์ยังเดินและยังบันทึกว่า "ไม่มีข้อมูลเข้า"
5. `npm run db:dump` ดึงข้อมูลกลับมาเก็บที่บ้านได้จริง
6. ตรวจฐานบนคลาวด์ด้วยคิวรีจริงกับ production แล้วต้องไม่มี **(ก)** LINE id ดิบ **(ข)** เนื้อข้อความที่พิมพ์
   **(ค)** คอลัมน์ชื่อ/เบอร์/อีเมลของคน — แล้วแนบผลลงบันทึกคำตัดสิน
   · ⚠ ข้อนี้เป็น **การตรวจของคน ไม่ใช่ของอัตโนมัติ** — ยาม `schema/privacy-guard.mjs` ถูกถอดโดย D-P0-06
     ถ้อยคำเดิมเขียนว่า "ตรวจด้วยสคริปต์ ไม่ใช่ด้วยตา" ซึ่งบังคับสิ่งที่คำตัดสินอีกใบห้ามไว้
     ⇒ ติ๊กผ่านไม่ได้ตลอดกาลไม่ว่าระบบจะปลอดภัยแค่ไหน (แก้ถ้อยคำ 2026-08-28 · ดู D-P0-17)
   · `person_code` ที่พ้องกับชื่อคน **ไม่นับว่าตก** — เป็นข้อยกเว้นที่เจ้าของระบบตัดสินไว้ (D-P0-17)
7. code-reviewer ตรวจผ่าน และรายงานให้พี่เต้เห็น
