## ✅ สองข้อนั้น เจ้าของระบบเคาะแล้ว 2026-08-29

### ① D-009 **ยืนยันตามเดิม** — "ไฟล์รูป/วิดีโอ = homelab เท่านั้น"
คำตัดสิน: *"ไฟล์รูป/วิดีโอ = homelab เท่านั้น ยืนยัน"* ⇒ **ห้ามเก็บไฟล์ถาวรฝั่ง cim-server**

**ผลต่อสถาปัตยกรรม — เปลี่ยนจาก "ย้ายเจ้าของ" เป็น "ย้ายแค่ตัวรับ":**
```
เดิม :  กลุ่ม → OA เก่า(homelab) → homelab เก็บ → เราขอ URL ผ่าน MCP
ใหม่ :  กลุ่ม → OA เรา → เราดาวน์โหลดจาก LINE → **ส่งต่อให้ homelab ทันที** → เราถือแต่ URL
```
เส้นแบ่งที่ยังคงเดิมทุกประการ: **homelab เป็นเจ้าของไฟล์ · เราเป็นเจ้าของ "คน/สิทธิ์"**
สิ่งที่เปลี่ยนคือ *ใครรับของเข้ามา* ไม่ใช่ *ใครเก็บของ* ⇒ ไม่ขัด D-009 และไม่ขัด CONTRACT §6
ในสาระสำคัญ (แต่ยังต้องแก้ถ้อยคำ §6 เพราะเขียนว่า "ฟังแชตกลุ่ม = homelab")

⚠ **โจทย์ใหม่ที่เกิดจากคำตัดสินนี้ — ต้องออกแบบให้ตอบได้ก่อนลงมือ:**
1. **homelab ยังไม่มีทางรับไฟล์เข้า** — MCP เป็น read-only ตามสัญญา · สะพานเป็นทางเดียว homelab→เรา
   ⇒ ต้องมีใบสั่งให้ homelab สร้าง endpoint รับไฟล์ (tailnet + กุญแจ + idempotent ด้วย messageId)
2. **LINE เก็บ content ให้ชั่วคราว + homelab availability 96%** (เงียบยาว 10 ชม. และ 5 ชม. ในสัปดาห์เดียว)
   ⇒ homelab ล่มตอนรูปเข้า = **รูปหายถาวร** ต้องมี "ที่พักระหว่างทาง" พร้อม retry
   · **ที่พัก ≠ ที่เก็บ** — ต้องนิยามให้คมไม่ให้กลายเป็นคลังที่สอง:
     เก็บไบต์ไว้จนกว่า homelab ยืนยันรับแล้วลบทันที · มี TTL แข็ง · เกิน TTL = **ส่งเสียงเตือน ห้ามลบเงียบ**
     · **รายงานต้องอ่านจาก URL ของ homelab เสมอ ห้ามอ่านจากที่พัก** (ไม่งั้นกลายเป็นความจริงสองชุดจริง ๆ)
   · ที่พักนี้เข้าข่าย D-009 ไหม — **ต้องให้เจ้าของระบบเคาะอีกครั้งก่อนเขียนโค้ด**
3. **รูปเก่า 12 วันที่ homelab ถืออยู่ไม่ต้องย้าย** — มันอยู่ที่เดิมอยู่แล้ว (ข้อดีที่ตามมาจากคำตัดสินนี้)
