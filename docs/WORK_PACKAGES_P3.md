## 4. 🔴 สิ่งที่ **ไม่** ครอบ — พูดตรง ๆ ไม่กลบ

1. **ตัวเดินไม่มีตัวกด — บันไดเตือนยังไม่เคยเดินเอง**
   ✅ ตรวจสด: `Get-ScheduledTask` เห็น task ขึ้นต้น `ksk-` **39 ตัว** ไม่มีตัวไหนชื่อหรือมี argument
   ที่มีคำว่า `escalat` (ใกล้ที่สุดคือ `ksk-task-remind` ซึ่งเป็นตัวทวงเดิม คนละตัว)
   · `grep` ทั้งรีโป: ไม่มีไฟล์ใดเรียก `bin/task_escalate.php` เลย นอกจากยามที่อ่านซอร์สมันเอง
   ⇒ **`bin/task_escalate.php` เป็นสคริปต์สั่งมือล้วน** · ประโยค "ของมันเดินอยู่จริง" ใน `aim/CLAUDE.md` §3
   ถูกครึ่งเดียว: **โค้ดมีจริงและผ่านยาม แต่ไม่มีอะไรกดให้มันทำงาน**
   · แก้ได้ด้วยการสร้าง task 1 ตัว (ไม่งอกยามใหม่ — เป็นตัวเดินงาน ไม่ใช่ยาม) **แต่ต้องเจ้าของระบบเคาะ**
   เพราะมันส่ง LINE ถึงพนักงานจริง (กติกา "ทุกฟีเจอร์ต้องผ่านพี่เต้คนเดียวก่อน")
2. **ยังไม่ยืนยันว่า `tbl_escalation` มีแถวจริงสักแถว** — ต้องคิวรีฐาน ซึ่งอยู่นอกสคริปต์ที่ได้รับอนุญาตให้รันรอบนี้
   (สอดคล้องกับข้อ 1: ถ้าไม่มีอะไรรัน ตารางก็ควรว่าง)
3. **เกณฑ์ ② ไม่เคยถูกทดสอบกับฐานจริง** — ยามตรวจว่า "ซอร์สมีคำว่า `INSERT IGNORE`" ไม่ได้ยิงซ้ำ
   แล้วดูว่าถูกกันจริง · เป็นจุดบอดชนิดเดียวกับบทเรียน H5 ("ยามที่เฝ้าผิดชั้น")
4. **selfcheck นับ push รวมทั้ง estate** ไม่แยกว่า escalation กินไปเท่าไร ⇒ ตอบได้ว่า "วันละกี่ push"
   แต่ตอบไม่ได้ว่า "บันไดเตือนกินโควตาเท่าไร"
5. **ไม่มี "สมุดบันทึกการตัดสิน" ที่คนเปิดดูได้** — `aip_journal()` เขียนลงฐานจริง แต่ไม่มีหน้าจอ/รายงานไหนอ่านมัน
   (สเปก §15–§17 พูดถึงสมุดบันทึกไว้ · ของที่มีคือตัวเขียน ไม่ใช่ตัวอ่าน)

**⇒ อ่านใบนี้ให้ถูก:** P3 ปิดเพราะ**เจ้าของระบบเคาะว่าไม่ทำต่อ** ไม่ใช่เพราะประตูผ่านครบสามข้อ
ข้อ 1 ข้างบนคือความจริงที่ต้องขนไปด้วยเวลาพูดถึง P3 — ห้ามรายงานว่า "P3 เดินอยู่จริง" เฉย ๆ อีก
